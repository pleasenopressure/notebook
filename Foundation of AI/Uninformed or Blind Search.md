树搜索和图搜索的区别
**Tree search** treats each node as a distinct **path** in the search tree. It does **not** check whether a state has been seen before, so the **same state can appear many times** via different paths. As a result, tree search may **re-expand duplicates**, waste time, and can even get stuck in loops in cyclic state spaces (especially with DFS).**树搜索**将每个节点视为搜索树中的一条独立**路径** 。它**不**检查某个状态是否已被出现过，因此**同一个状态可能通过不同的路径多次出现** 。结果，树搜索可能会**重复展开重复的路径** ，浪费时间，甚至在循环状态空间中陷入循环（尤其是在使用深度优先搜索时）。

**Graph search** treats nodes as **states** in the underlying state-space graph. It performs **duplicate detection** using an **explored/closed set** (and often also checks the frontier). When generating successors, a state that is already in the explored set or frontier is **not added again**, so repeated expansions are reduced. This usually makes search **more efficient**, but it requires **more memory** to store visited states.**图搜索**将节点视为底层状态空间图中的**状态** 。它使用**已探索/已关闭的集合** （通常还会检查边界）进行**重复检测** 。在生成后继节点时，已在已探索集合或边界中的状态**不会再次添加** ，从而减少了重复扩展。这通常会**提高搜索效率** ，但需要**更多内存**来存储已访问的状态。

Regarding **optimality**, duplicate handling matters. For example, with **BFS** and **unit step costs**, graph search is still optimal and avoids redundant work. For **A***, tree search is optimal with an **admissible heuristic**, while in graph search optimality may require stronger conditions (e.g., a **consistent** heuristic) or the ability to reopen states if a cheaper path is found.关于**最优性** ，重复操作的处理至关重要。例如，对于广度优先搜索 **（BFS）** 和**单位步长成本** ，图搜索仍然是最优的，并且避免了冗余工作。对于 **A*** 算法，在具有**可接受启发式的**情况下，树搜索是最优的；而对于图搜索，最优性可能需要更强的条件（例如，一致的启发式），或者允许在找到更便宜的路径时重新打开状态。
