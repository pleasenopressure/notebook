## 推荐阅读

### 1. 机器人如何判断“什么时候应该说话”？

[阅读：如何智能插入对话](./reachy%20robot开发日志/如何智能插入对话.md)

围绕 Reachy Mini 的多人讨论辅助场景，记录从逐句回复到基于会话状态判断介入时机的设计演进。

重点讨论：

- 如何通过发言时长、轮次和沉默等信号描述讨论状态；
- 如何确定介入动作与目标参与者；
- 如何在动作确定后，让 LLM 生成受约束的表达；
- 如何通过日志保留介入原因，支持后续分析。

这篇笔记体现了我对**状态管理、决策逻辑与语言生成之间职责划分**的思考。

### 2. “谁在说话”和“机器人应该看向谁”有什么区别？

[阅读：如何分辨 speaker](./reachy%20robot开发日志/如何分辨speaker.md)

记录发言者区分方案的演进，包括声纹方案的尝试、基于麦克风设备的身份绑定，以及声音方向信息的探索。

核心问题是：完整转写需要等待语音处理完成，而实时朝向需要更快的信号。因此，发言者归属、快速注视目标和语义介入需要分别处理。

笔记同时保留各方案的限制与取舍，区分实验思路和实际采用的实现。

## 我的笔记方式

我通常围绕以下问题组织学习与复盘：

- **概念是什么？** 用自己的语言解释定义，保留必要的数学表达。
- **为什么这样做？** 记录方法背后的直觉、假设与适用条件。
- **如何实现？** 结合代码、数据流或项目模块理解具体行为。
- **遇到了什么问题？** 保留失败尝试、限制和修改原因。
- **哪些结论有证据支持？** 区分理论解释、方案建议、实际实现与实验结果。

不同笔记处于不同整理阶段，既有较完整的专题总结，也有课程速记、问题清单和开发草稿。
