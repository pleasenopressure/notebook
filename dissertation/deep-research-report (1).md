# 智能家居×LLM行动规划课题：第二次导师会谈的问答清单与议程

本清单将毕业要求、发表策略、里程碑、资源、技术路线、评估、伦理与求职等关键问题结构化，便于一次会谈对齐并形成可执行行动项。

## 会谈目标与准备材料

本次（第二次）会谈的目标，不是再泛谈选题，而是把“**学位达成路径**（毕业/论文/答辩）”“**研究产出路径**（投稿/开源/署名）”“**工程落地路径**（平台/资源/里程碑/评估）”三条线在一次会谈里收敛成：明确的时间节点、最低可交付物、资源承诺与审批流程（或需要你去找谁确认）。由于你未指定学校/国家，很多硬性规则（学分、论文长度、提交材料、审批节点）确实会差异很大，例如英国体系常见以“学分/模块/论文”组织硕士，但不同学校可能采用不同credit体系或ECTS映射，需要以本校研究生院/学院手册为准。citeturn0search0turn0search4

建议你会前准备并带到会场（纸质或一页PDF都行）：

- 一页“项目框架图 + 当前进展”（你上一份报告的框架压缩成1页：Planner、RAG、Abstain/Clarify、多模态工具、执行监控、仿真平台等）
- 一页“拟定里程碑/时间表草案”（本报告后面提供模板，你根据自己学期周数填具体日期）
- 一页“风险清单 + 需要导师拍板的决策点”（例如：是否使用闭源API、是否必须做真实机器人验证、目标会议优先级）
- 你所在项目/课程的官方Handbook或链接（若你还没拿到，至少带上“项目名称/项目代码/就读类型：taught MSc vs research master”等信息，方便导师快速定位责任边界）

## 外部规范与惯例速览

这一节用于“给问题提供依据”，让你在问到细节时能说明为什么要问、问什么最关键。

硕士学位的学分与结构在不同国家/学校差异明显。在英国语境下，QAA的Higher Education Credit Framework提到**更典型的（more typically）硕士学位最少180 UK credits，并对应约90 ECTS**，但同时也强调并非所有学位授予机构都使用credit或可能采用ECTS。citeturn0search4turn0search0 这意味着：你不能凭“行业常识”推毕业条件，必须把“本校/本系的正式条款”问清楚。

论文/答辩层面，不同学校对“字数/格式/提前报备/提交材料”要求非常具体且差异大。举例：Swansea的研究学位提交指南对MA/MSc by Research给出**40,000词主文上限**（不含附录/参考文献等），这说明很多学校会把字数、结构、提交规则写死在手册里。citeturn2search2 又如University of Birmingham要求**提交前至少三个月递交Intention to Submit类表格**，反映出有些学校存在“提前报备—指派评审—再提交”的行政流程。citeturn2search18 因此你需要把“时间节点与审批链”问到可执行的粒度。

发表与署名方面，真正能“压住争议”的是出版方/学会的公开政策。IEEE作者中心给出作者资格的三条核心条件（重要智力贡献、参与撰写/修订、批准最终版本），并强调通讯作者在署名合规与沟通中的责任。citeturn1search0 ACM也有明确的作者政策，要求作者对作品有实质贡献并承担责任。citeturn0search7turn0search3 这些政策非常适合你在会谈中用于“提前对齐署名与贡献记录方式”。

投稿规范方面，你关心的目标会议/社区里，**可复现清单与匿名审稿要求已成为强约束**：  
- ICLR明确双盲，并说明**相关arXiv论文不破坏匿名**，允许按其dual submission政策在arXiv存在预印本（但仍要求投稿稿件匿名）。citeturn0search2turn3search18  
- ICRA 2026明确采用**double-anonymous**，并在FAQ中写明：**上传到预印本服务器（如arXiv）的论文，只要不同时投其它会议/期刊，也可投稿ICRA**。citeturn1search1turn3search2 同时，ICRA 2026 final版本对页数限制非常严格，明确8页（包含各部分）并提示不合规会被移出论文集。citeturn1search5  
- NeurIPS要求作者完成paper checklist，并明确“不包含checklist会desk reject”。citeturn0search1turn0search9 同时提供代码/数据提交与长期保存建议（强调链接、持久标识符等）。citeturn0search5  
- AAAI-26要求提交时完成可复现清单（reproducibility checklist），并提供专门页面。citeturn3search7turn3search3  
- CHI对匿名化有清晰要求（第三人称引用自引等），并在publication-ready说明中鼓励green open access（含arXiv等非商业仓库）以符合ACM green OA政策。citeturn3search1turn3search21  

伦理与隐私方面，如果你计划采集家庭音视频、用户交互日志、或把带个人信息的数据发给云端模型，就必须把GDPR/机构政策与伦理审批纳入计划。EDPB面向中小组织的指南强调处理个人数据需要合法依据（legal basis）。citeturn2search29 UKRI关于GDPR与研究的FAQ也强调研究机构需要明确处理个人数据的合法依据，并提到在很多情境中“伦理审批到位”可作为保障措施的一部分。citeturn2search13

你的实验平台与工程落地也有“惯例可借”：AI2-THOR官方介绍列出其覆盖多房间类型、上千对象、支持open/close与on/off等视觉状态变化，并支持多智能体，这与“智能家居动作规划+多模态感知”高度匹配。citeturn3search0turn3search8 在智能家居侧，Home Assistant提供面向LLM的内置Assist API暴露机制，并可通过注册intent扩展。citeturn1search3turn1search7 SMART-LLM的公开代码仓库可以作为你复现实验与构建对比基线的工程起点。citeturn2search3

## 面向导师的问答清单

下面每个主题都给出2–4个“可直接问出口”的问题，并在每个问题后标注目的与期望回答类型。凡标注“学校/国家差异较大”的，默认你无法自行推断，应以导师/系里/研究生院正式规定为准。

**毕业要求与学位流程（学校/国家差异较大，需确认）**  
- “我这个项目最终属于哪一种学位/模块要求：taught MSc dissertation、MSc by Research、还是MRes/课题型？对应的学位授予条件分别是什么？”（目的：确定你该遵循哪套规章；期望：明确分类 + 对应的官方条款/链接）  
- “毕业是否有硬性门槛：总学分/必修模块、最低均分/及格线、论文单独及格线、是否允许补交/重修？”（目的：把‘能毕业’的硬条件锁定；期望：明确规则与例外处理）  
- “论文的格式与提交要求：模板、字数/页数上限、是否必须含开源链接/附录、引用格式、是否需要Turnitin/相似度阈值？”（目的：避免最后阶段因为格式/查重翻车；期望：可操作清单 + 时间点）  
- “时间节点：最晚提交日期、是否需要提前提交‘Intention to submit’之类材料、答辩/口试时间窗、导师/学院签字审批链路是什么？”（目的：把流程拆成可排期任务；期望：明确时间节点 + 审批流程/负责人）

**论文发表目标与投稿策略（学校/导师差异大，需确认）**  
- “您对我硕士毕业的发表期望是：必须有论文录用/接收吗？更看重量（顶会/期刊）还是数量？没有录用但有arXiv/技术报告是否可接受？”（目的：对齐‘毕业 vs 发表’的硬绑定程度；期望：定性原则 + 最低标准）  
- “是否必须第一作者？如果不是第一作者，是否仍能满足毕业或组内考核？共同一作是否认可？”（目的：提前规划署名与贡献；期望：明确要求/不要求）  
- “预印本（arXiv）策略：您倾向于‘投稿前发/投稿后发/录用后发’？对于双盲会议，您希望我如何避免影响匿名（例如在comments里不写投稿信息等）？”（目的：避免违反会议匿名或组内策略；期望：明确策略 + 可执行注意事项）  
- “共同作者署名规则：组内通常按贡献排序还是PI固定末位？通讯作者一般由谁担任？我们是否需要写贡献声明/记录（对齐IEEE/ACM作者责任）？”（目的：减少署名纠纷并符合出版伦理；期望：明确规则 + 贡献记录方式）

**项目里程碑与时间表（需确认与你学期同步）**  
- “您希望我把项目拆成哪些阶段（基线复现、系统搭建、多模态扩展、评估、写作）？每阶段的验收标准是什么？”（目的：把抽象目标变成可验收deliverables；期望：阶段划分 + 验收清单）  
- “最低可交付物（MVP）是什么？例如：仅仿真端到端、是否必须接入真实智能家居平台、是否必须做实体机器人验证？”（目的：锁定‘最小毕业/最小可发表’范围；期望：明确最低要求）  
- “评估指标达成标准：成功率/效率/安全（拒答率）等指标，您希望达到什么水平才算论文/毕业合格？”（目的：避免‘做完了但不够好’；期望：定量阈值或可对标的baseline）  
- “缓冲期怎么安排：写作与实验收尾需要预留多少周？如果关键模块延期（如视觉/语音）是否有降级方案？”（目的：把风险前置；期望：时间缓冲 + 风险应对策略）

**资源与支持（实验室/经费/权限差异大，需确认）**  
- “可用计算资源：GPU/集群配额、是否允许跑闭源API（费用/额度由谁承担）、数据存储与备份规范是什么？”（目的：确认你实际能跑多大模型/多少实验；期望：资源承诺 + 使用规范）  
- “仿真平台与许可：AI2-THOR/Unity等是否有实验室已有环境或推荐版本？是否有组内复现脚本/镜像/容器？”（目的：减少环境坑与重复劳动；期望：版本建议 + 共享资产）  
- “硬件资源：机器人/摄像头/传感器是否可借用？使用流程（培训、排期、责任协议）是什么？”（目的：决定是否能做真实验证与多模态；期望：可用清单 + 借用流程）  
- “经费/助研机会：是否有RA小时、设备采购/云服务报销渠道、投稿/参会资助可能？”（目的：决定投入规模与投稿可行性；期望：资源承诺或申请路径）

**方法学与技术路线确认（与导师偏好强相关，需拍板）**  
- “您希望我把‘SMART-LLM式多阶段规划’作为主基线复现并扩展吗？还是更希望走‘工具调用/结构化计划/行为树执行’的工程路线？”（目的：对齐主线贡献；期望：方法偏好 + 必做基线）  
- “LLM选择：您是否支持我使用闭源API（如OpenAI）做Planner/多模态工具？如果学校/项目对数据出境或个人数据有要求，我们怎么合规？”（目的：避免合规风险 + 决定系统能力上限；期望：允许/不允许 + 合规边界）  
- “多模态模块优先级：在视觉/语音/传感器/社交信号中，您认为哪一个最能提升论文贡献与求职竞争力？最少做几个模态才有意义？”（目的：避免摊太薄；期望：优先级排序 + 최소范围）  
- “是否需要实现SayCan或SayCan-lite用于可行性约束/技能选择？还是用更轻量的可行性过滤器即可？”（目的：控制工作量并提高可执行性；期望：是否必做 + 复杂度上限）  
- “对可解释性/安全性证明的要求：您更希望我做形式化证明，还是以Abstain/Clarify机制 + 实证评估为主？”（目的：确定写作重心与实验设计；期望：定性建议 + 需要的证据类型）

**实验设计与评估（决定论文质量的关键）**  
- “基准/数据集选择：您希望我主要跑AI2-THOR（含SMART-LLM基准设置）还是也要引入AbstainEQA式‘拒答/不确定性’评测？两者怎么组合最合理？”（目的：建立强对比与清晰贡献；期望：基准清单 + 组合方案）  
- “对比基线：除了LLM Planner，我是否需要加入经典规划（如PDDL/启发式规划）或规则系统作为下界？您希望哪些消融是必须的？”（目的：保证论文评审可接受；期望：必做baseline与消融列表）  
- “统计与重复：您希望每个设置跑多少seed/多少episodes？是否要求显著性检验或置信区间？”（目的：避免结果不稳被质疑；期望：定量要求）  
- “失败分析：您希望我按哪种分类做error taxonomy（例如指代不清、状态不可得、执行失败、工具错误等）？需要录像/可视化到什么程度？”（目的：提升论文说服力与可解释性；期望：分析框架 + 展示标准）

**合作与发表流程（导师工作流差异大，需确认）**  
- “沟通频率：您希望我每周/每两周同步一次？每次同步需要提供什么（周报、实验表格、demo视频）？”（目的：形成稳定节奏；期望：明确频率 + 交付格式）  
- “代码/论文审阅流程：提交PR还是发zip？您希望提前多久看初稿？是否有组内‘内部预审’（同门先review）？”（目的：避免最后时刻来不及改；期望：流程与时限承诺）  
- “投稿策略：您希望优先投哪类会议/期刊（机器人/ML/HCI）？如果第一目标未中，是否有备选梯队与时间窗口？”（目的：形成可执行投稿路线；期望：目标名单 + 备选策略）  
- “贡献声明与文档化：我们是否统一使用贡献记录（例如按模块/实验/写作记录），以便署名与推荐信更有证据？”（目的：将贡献可追溯；期望：采用/不采用 + 模板）

**风险、伦理与隐私（学校/国家差异大，需确认）**  
- “是否需要伦理审批（IRB/学院伦理）？如果我做用户访谈/家庭场景录音录像/收集日志，最小审批流程是什么？”（目的：避免合规红线；期望：是否需要 + 申请路径与周期）  
- “数据合规：个人数据（视频/语音/家庭设备状态）能否上传云端？是否必须去标识化、加密存储、限定保留期限？”（目的：对齐GDPR/学校政策；期望：合规边界 + 技术要求）  
- “家庭场景安全策略：涉及门锁/炉灶/摄像头等敏感设备，是否需要‘人类确认’或权限分级？导师期望的安全机制最低要求是什么？”（目的：降低现实风险并增强论文可信度；期望：最低安全设计）  
- “知识产权与数据使用：我能否使用导师/组内已有代码与数据？使用时是否有署名、许可、对外开源限制？”（目的：避免IP纠纷；期望：许可条款 + 对外发布边界）

**求职与成果展示（与导师支持度高度相关）**  
- “您是否支持我把项目做成可展示的demo（视频+开源仓库+复现实验脚本）？哪些内容可以公开、哪些必须内部保留？”（目的：提前规划作品集；期望：可公开范围 + 审批方式）  
- “论文/代码开源要求：您希望我达到哪个复现标准（一键运行、容器、数据下载脚本）？与NeurIPS/AAAI等checklist的对齐程度要到什么水平？”（目的：对齐‘开源/复现’投入；期望：明确标准）  
- “推荐信与实习：您通常在什么条件下愿意写推荐信？是否可能引荐合作实验室/工业联系，或提供暑期实习合作机会？”（目的：把求职路径前置；期望：条件清单 + 可能机会）  
- “成果包装：您建议我把亮点放在‘多模态智能家居助手’还是‘安全可靠的LLM规划框架’？哪些故事线最适合我申请的岗位类型？”（目的：让研究叙事与岗位匹配；期望：定性建议）

## 里程碑与时间表草案

下面给出一个“可带去会谈、让导师直接改”的草案。你可以把“周数/日期”换成你本校的学期安排与最终deadline。该草案默认你以“AI2-THOR仿真 + 智能家居工具层（Home Assistant或等效抽象）”作为主验证环境。citeturn3search0turn1search3

阶段一：范围锁定与基线复现（建议2–3周）  
交付物：跑通SMART-LLM/同类任务规划基线或至少复现其关键设置；产出一张“基线结果表+失败案例库”；确定最终评估指标与实验protocol。citeturn2search3turn3search8

阶段二：端到端骨架搭建（建议3–4周）  
交付物：端到端MVP（文本指令→结构化计划→工具调用→状态回传→再规划）；具备最小错误处理（工具失败/状态不满足即回滚或重试）；完成日志与可复现实验脚手架。

阶段三：可靠性与安全机制（建议3–4周）  
交付物：实现Abstain/Clarify优先策略（不确定性触发拒答或补充观测/提问）；明确“敏感设备动作”的权限与确认机制；给出安全评估指标与案例库。该阶段与UK/EU数据合规与伦理审批可能强耦合，需要预留审批周期。citeturn2search13turn2search29

阶段四：多模态增强（建议3–5周，按优先级取舍）  
交付物（择优）：
