# 如何智能插入对话

> 本文记录 Reachy Mini group facilitator 从“每句话都回复”到“先判断是否介入，再生成受约束措辞”的演进。以下描述以当前 worktree `baby-reachy-mini-companion` 的代码为准。

## 问题定义：智能介入不是让 LLM 自己决定一切

机器人要分开完成三个问题：

1. **现在是否应该介入？**
2. **如果介入，执行哪一种 action、面向谁？**
3. **已经确定 action 和 target 后，具体说什么？**

当前实现采用“确定性 meeting-state / safety rule 做 1 和 2，LLM 只做 3”的结构。这样每次介入都能在日志中给出 `action`、`should_intervene`、`reason` 和 `target_speaker`，不会让 LLM 随意改变策略。

## 阶段一：没有介入机制和会话记忆，直接对话

最初的流水线近似为：

```text
收到一句语音 → STT → 把当前一句交给 LLM → TTS
```

实验表现是：

- 机器人只能被动回应刚刚一句，缺乏多人讨论的上下文；
- 不知道谁已经说得很多、谁还没有参与；
- 不理解沉默是短暂停顿还是话题已经停滞；
- 每收到一句都可能插话，频率过高；
- 生成内容可能与更早的讨论脱节，出现前言不搭后语。

根因不是单纯“LLM 不够聪明”，而是输入中没有结构化会议信号，也没有独立的介入控制层。

## 阶段二：引入 MeetingStateTracker 和决策阈值

### 2.1 MeetingState 记录什么

当前 `local/mediation.py::MeetingStateTracker` 在 `record_turn()` 中保存每个有效 turn：

- `speaker`：发言者；
- `text`：STT transcript；
- `duration_s`：该段音频时长；
- `timestamp_mono`：单调时钟时间；
- `silence_before_s`：与上一 turn 的间隔；
- `include_in_balance`：是否可用于参与平衡统计。

每次 snapshot 会生成：

- 当前 speaker 和已配置参与者；
- 最近最多 10 个 turns / transcript；
- 每人总发言时间、滚动窗口发言时间、总轮次和窗口轮次；
- speaking share、turn share、dominant speaker、under-participating speaker；
- 参与熵 entropy；
- 当前可用的视觉措辞上下文。

只有已确认身份且允许计入 balance 的 turn 才应影响参与平衡。unknown、校准未完成或不可信来源不能被假装成某个参与者。

### 2.2 两个决策时机

当前不是每个音频块都调用 LLM，而是在两个边界上做确定性判断：

#### A. 一句话刚结束：`decide()`

大部分普通情况不立即介入，只返回 `awaiting_silence_confirmation`。例外是需要及时处理的高置信度事件：

- 最新一句命中明确的不尊重/辱骂词 → `respect_interruption`；
- 最近窗口出现强参与失衡 → `encourage_participation`，target 是较少发言的人。

#### B. 持续沉默：`decide_during_silence()`

silence monitor 在音频 pipeline 稳定、没有新 turn、没有正在播放或生成的介入时检查沉默。它会按优先级选择：

1. cooldown 或已有 intervention in flight → 不介入；
2. 有足够证据的参与失衡 → `encourage_participation`；
3. 简短敷衍回应后继续沉默 → `deepen_discussion`；
4. 达到长沉默 → `ice_breaking`；
5. 否则继续 `no_intervention`。

当前默认阈值来自 `config.py`：

- 短沉默：2.0 秒；
- 可以开始考虑介入的沉默边界：2.8 秒；
- 长沉默：4.0 秒；
- 参与平衡至少需要 4 个 turns 且会话已持续至少 20 秒；
- 一般 intervention cooldown：30 秒；
- respect 类 cooldown：12 秒；
- balance 类 cooldown：45 秒。

这些是当前默认值，不是普遍心理学结论；实验时可通过环境变量调整，并应在 evaluation 输出中记录实际配置。

### 2.3 参与失衡如何判断

代码同时考虑发言时间和轮次，而不是只数句子。常规失衡规则包括：

- dominant speaking share 大于 65%，且 under-participant 小于 20%；或
- 最大与最小 turn count 的比例达到 3:1。

为了允许更及时的 turn-boundary 介入，最近窗口还有更强的条件，例如 dominant share 至少 75%、under share 不高于 15%、dominant 至少 4 turns，或同一 speaker 连续至少 5 turns 且近期发言时间达到 20 秒。

只有证据量达到 `balance_min_turns` 和 `balance_min_elapsed_s` 后才启用这类判断，防止开场第一两句就把自然差异误判成失衡。

### 2.4 从决定到生成文本

真实链路是：

```text
可信 participant speech
        ↓
MeetingStateTracker.record_turn()
        ↓
snapshot(recent turns + balance + silence)
        ↓
decide() / decide_during_silence()
        ↓
InterventionDecision(action, should_intervene, reason, target)
        ↓
build_llm_input() 生成严格的 Facilitation Request
        ↓
LLM 只生成符合 action 的短句
        ↓
SafetyPolicy 确定性后处理
        ↓
TTS + 目标朝向 + session log
```

如果 `should_intervene=false`，不会为了“看看 LLM 怎么说”而调用介入生成路径。

## 阶段三：对需要即时反应的情况设置规则

对明确辱骂或不尊重表达，等到 4 秒长沉默才回应会错过时机。因此 `_has_respect_violation()` 使用规范化文本和受控词表做确定性检测，在 turn boundary 直接选择 `respect_interruption`。

这样做的优点是低延迟、可测试、可解释；限制是关键词无法完整理解反讽、引用和复杂上下文，所以规则应保持保守。当前代码也为 respect action 单独设置 12 秒 cooldown，避免同一冲突片段被连续打断。

LLM 不负责重新判断“这是不是冒犯”，而是根据已经选定的 action 生成简短、非指责性的调解措辞。

## 阶段四：话题库与 ice-breaking

### 4.1 为什么需要 预先准备的 ice-breaking 话题库

当双方长时间沉默或讨论耗尽时，机器人需要一个安全的新问题。完全依赖 LLM 即兴生成容易：

- 重复已经问过的问题；
- 忘记当前讨论，突然回到固定实验题目；
- 生成不适合实验场景的话题。

因此当前代码通过 `OfflineKnowledgeRetriever` 从本地 curated corpus 检索候选证据，再把最多一个相关想法作为中性提问参考。

### 4.2 当前检索优先级

`handler.py::_augment_mediation_input_with_knowledge()` 会判断会话阶段：

- 开场、还没有实质讨论：查询可包含配置的实验 topic；
- 已有实质讨论：查询切换为最近最多 6 个 turns 的内容，不再固定围绕初始问题；
- 检索时排除本 session 已经成功使用过的 `doc_id`；
- prompt 还列出最近已经问过的问题，禁止重复或近似改写；
- 知识只有在成功播出后才提交为“已使用”，生成失败不会错误消耗候选。

### 4.3 ice-breaking 输出结构

`build_llm_input()` 根据真实 transcript 选择结构：

- 开场无实质讨论：只生成一个新的安全问题；
- 已有讨论但无可靠共同点：明确过渡 + 一个新问题；
- 至少两名参与者的内容支持一个具体共同点：保守共同点总结 + 明确过渡 + 一个新问题。

不能虚构共识，也不能把互不相关的话说成双方同意。输出必须是一个原子介入，且只包含一个问号。

## 阶段五：引入 VLM 描述环境与人物情绪

最初单帧分析包含的信息太少，容易把瞬间表情、模糊画面或偶然遮挡当成稳定状态。后来改为在一个时间窗口中采样多张图片，组成 contact sheet 交给本地 VLM，从而同时观察：

- 左右座位的人物与可见性；
- apparent affect（表面情绪）、valence 和 arousal；
- 环境概况与变化；
- 非敏感服饰信息等可用于轻量 icebreaker 的现场线索。

VLM 输出会携带 confidence、capture age、stale 和 input-quality 等状态。低置信度、过期或证据不完整的结果不能用于显式情绪措辞。

## 阶段六：用 MediaPipe 提供高频、低延迟观察

如果让 VLM 承担每一帧的在场判断、头部朝向和注意力估计，推理延迟会远高于会话控制所需频率。因此当前视觉系统分成两层：

- **MediaPipe + OpenCV 快速层**：高频提取 face landmarks、head pose、presence/ambiguity 等结构化信息；
- **VLM 慢速层**：对一段时间的 contact sheet 做环境和 apparent affect 的语义描述。

MediaPipe 的 neutral pose 也需要稳定校准；未校准、人物缺失或座位歧义时，相关值标记为 raw/untrusted，不能伪装成可靠注意力结论。

## 阶段七：最终融合边界——视觉只调整措辞，不决定是否介入

这是当前实现中最重要的安全边界。`local/vision_fusion.py` 的模块约束是：

> 文本、音频、沉默和参与平衡仍是权威控制信号。视觉只能为一个**已经选定**的 action 增加受限措辞提示；它不能创建、延迟、压制、取消或重新指定 intervention。

因此最终顺序不是“先等 VLM 看完，再决定要不要说”，而是：

```text
MeetingStateTracker 先选定 action / target / should_intervene
                         ↓
读取此刻已有且未过期的视觉结果（不等待新的 VLM）
                         ↓
只生成 tone、现场观察或极受限的情绪措辞提示
                         ↓
原 action 和 target 保持不变
```

具体约束包括：

- `encourage_participation` 只可使用目标参与者的可信 affect 调整语气；
- `ice_breaking` 可在 confidence 足够且信息新鲜时使用一条环境观察；
- 环境观察必须与最近讨论自然连接，否则必须明确表示换话题；
- 已使用的 scene fingerprint 会去重，避免反复提同一环境细节；
- 与在场事实冲突的“空座位/缺席”描述会被过滤；
- camera、model、confidence 等内部信息不能说给参与者；
- 视觉证据不足时直接退化为纯文本策略，不改变已选 action。

## 名字、目标和动作的双重保护

LLM prompt 会明确：

- 有单独 target 时，必须说出该 target 的名字；
- 没有单独 target 时，要说出两位参与者的名字；
- 同一个名字在一句话内不得重复。

但 prompt 不是最终保证，因此 `FacilitatorSafetyPolicy` 在送入 TTS 前还会做确定性后处理。目标朝向也来自语义 target，而不是 DoA：

- Jack → 右侧 `+30°`；
- Mary → 左侧 `-30°`；
- 面向两人/无单独目标 → 中心 `0°`。

这保证 LLM 措辞、日志 target 和机器人头部方向使用同一语义结果。

## 防止重复介入和竞态

沉默介入不仅靠一个秒数阈值。handler 还会检查：

- audio pipeline 是否稳定，是否还有待完成的语音段；
- 是否已经有 intervention in flight；
- 当前 silence episode 是否已介入；
- `conversation_revision` 在生成期间是否变化；
- TTS 或机器人输出是否正在占用通道；
- action-specific cooldown 是否生效。

一旦某个 silence episode 选中介入，会在等待 LLM 前先 latch，防止慢生成期间再次启动相同介入。如果参与者在生成期间恢复说话，系统还需要按 intervention lifecycle 记录 stale/cancelled/delivery 状态，而不能只看一条“LLM generated”日志就认为机器人完成了介入。

## 当前 action 总览

| action | 典型触发 | target | 期望输出 |
|---|---|---|---|
| `no_intervention` | 证据不足、短暂停顿、cooldown | 无 | 不调用介入输出 |
| `respect_interruption` | 明确不尊重词命中 | 通常全组 | 简短、冷静、非指责地恢复尊重 |
| `encourage_participation` | 强参与失衡 | 较少发言者 | 点名、低压力邀请其表达 |
| `deepen_discussion` | 浅层回应后继续沉默 | 视情况而定 | 紧扣最近具体内容追问原因、例子或取舍 |
| `ice_breaking` | 长沉默/话题耗尽 | 通常全组 | 总结/过渡（如有依据）+ 一个新问题 |

## 当前完整数据流示例

假设 Jack 连续发言，Mary 很少参与，随后出现沉默：

1. 多麦克风链路把可信 transcript 标为 `Jack`，`record_turn()` 累积 Jack 的发言时长和轮次；
2. 在至少 4 turns、至少 20 秒证据后，snapshot 显示最近窗口明显失衡；
3. `decide()` 或 `decide_during_silence()` 返回：

   ```text
   action=encourage_participation
   should_intervene=true
   reason=recent_participation_dominance
   target_speaker=Mary
   ```

4. VLM 若有新鲜且可信的 Mary affect，只能把措辞调整得更轻柔，不能把 target 改成 Jack，也不能取消该决定；
5. `build_llm_input()` 要求短句并说出 `Mary`；
6. SafetyPolicy 再检查名字与敏感元语言；
7. 机器人头部转向 Mary 的固定座位方向并播放 TTS；
8. session log 记录 decision、intervention id、生成文本、目标方向、播放/交付状态；
9. 30 秒 outcome window 后，系统可记录 Mary 是否回应、其 speaking share 是否变化，以及沉默是否结束。

## 评估时应怎样表述结果

应把不同层的成功分开：

- **决策基础设施成功**：给定 turn/silence 输入，action、target、reason 和时机符合预期；
- **文本生成成功**：LLM 输出满足结构、名字和安全约束；
- **音频路由成功**：文本已合成 PCM 并交给播放通道；
- **物理交付成功**：真实机器人完整、可听地播完，并正确面向目标；
- **介入有效**：参与者随后回应、平衡改善或沉默结束。

文本测试通过不能自动证明真实机器人完成了可听播放；当前 56 个文本场景的 objective evaluation 主要验证 timing/action 基础设施，不等于评价回答自然度，也不等于硬件 I/O 验收。

## 当前限制与后续改进

- 关键词规则对复杂语义和反讽的理解有限，应继续保持保守；
- 所有阈值来自当前工程实验设置，需要通过真实 HRI 数据校准；
- MediaPipe 的“朝向/专注度”只是可观察 proxy，不应直接宣称参与者心理上专注或不专注；
- apparent emotion 必须表述为受限的表面观察，并对 stale、遮挡和座位歧义做退化；
- RAG 只能提供安全候选，不应覆盖近期讨论；
- 视觉不得成为介入 timing gate；
- 应同时保存 raw decision、LLM input/output、TTS route 和 intervention outcome，方便复现实验。
