## chapter3.1 N-grams
### 📝 核心摘要 (Course Overview)

本节（3.1 N-Grams）介绍了语言模型的最基本形态：**N元语法模型**。其核心任务是根据历史上下文预测下一个词的概率。通过引入**马尔可夫假设（Markov Assumption）**，N-gram 将难以计算的完整历史序列简化为有限的局部窗口。模型通过**最大似然估计（MLE）**在语料库中利用相对词频来计算概率，并详细探讨了工程落地中防止数值下溢的**对数概率（Log Probabilities）**转换。

---

### 💡 教师重点复述 (Teacher's Emphasis)

- **重点：马尔可夫假设的“降维打击” (Page 40)**
    
    - **直观理解**：语言具有无限的创造性，我们不可能在语料库中找到所有长句子的精确出现次数（例如“The water of Walden Pond is so beautifully...”在整个互联网上也可能只出现过一次）。马尔可夫假设巧妙地通过“只看前面 N-1 个词”来近似整个历史，将原本属于指数级爆炸的搜索空间，降低到了可统计的范围内。
        
- **注意：为什么必须加 `</s>` 结束符？ (Page 41 脚注)**
    
    - **常见错误**：很多同学在计算句子概率时只算到最后一个词。如果不加句子结束符 `</s>`，模型就无法“学会”在何时停止生成。从数学上讲，缺少结束符会导致模型无法在所有可能长度的句子上形成一个单一的合法概率分布（概率总和不为1）。
    - 注意：![[Pasted image 20260221180207.png]]
        
- **工程防坑：不要直接连乘，用对数概率 (Log space)！ (Page 43)**
    
    - **为什么重要**：在计算整个句子的概率时（如几十个小数相乘），计算机的浮点数精度会很快遭遇**数值下溢（Numerical underflow）**，最后结果全变成 `0.0`。在所有实际的工程实现（包括现在的深度学习框架）中，**必须将概率转换为对数 (log)，把连乘转化为连加**。只有在最后需要向用户展示概率时，再 `exp` 转换回去。

### 📖 按章节详细讲解 (Section-by-Section Breakdown)

#### 1. 背景与链式法则 (Chain Rule) (Page 39)

- **目标**：计算给定历史上下文 $h$ 的情况下，下一个词 $w$ 的概率 $P(w|h)$。
    
- **链式法则推导**：根据概率论，一个完整句子（词序列 $w_{1:n}$）的联合概率可以拆解为一系列条件概率的连乘（Eq 3.4）：
    
    $$P(w_1, w_2, ..., w_n) = \prod_{k=1}^n P(w_k | w_{1:k-1})$$
    
    _问题在于：当 $k$ 很大时，$P(w_k | w_{1:k-1})$ 这个长历史条件概率根本无法通过统计语料库得出（数据极度稀疏）。_
    

#### 2. 马尔可夫假设 (The Markov Assumption) (Section 3.1.1, Page 40)

- 为了解决历史过长无法统计的问题，我们做了一个强假设：**当前词的出现概率只依赖于它前面的局部几个词**。
    
- **一般化 N-gram 近似** (Eq 3.8)：
    
    $P(w_n | w_{1:n-1}) \approx P(w_n | w_{n-N+1:n-1})$
    
    - **Bigram (2-gram, 二元)**：只看前面1个词 $\approx P(w_n | w_{n-1})$
        
    - **Trigram (3-gram, 三元)**：只看前面2个词 $\approx P(w_n | w_{n-2}, w_{n-1})$
        

#### 3. 概率估计：最大似然估计 (MLE) (Section 3.1.2, Page 41-43)

- **如何计算**：通过统计训练语料库中的**相对频率 (Relative Frequency)**。

- **使用对数 (Log Probabilities)**： $p_1 \times p_2 \dots \times p_n = \exp(\log p_1 + \log p_2 \dots + \log p_n)$ (Eq 3.13)
    
- **更长的上下文**：工业界（特别是神经语言模型出现前）广泛使用 Trigram, 4-gram 甚至 5-gram（如 Google 的 1 Trillion Web 5-gram 数据集）。
    
- **存储与计算优化**：需要用量化技术（Quantization，仅用 4-8 bits 存概率）、哈希表、后缀数组（Suffix arrays，如 infini-gram 项目）等数据结构来压缩内存。

### 🔤 专有名词与公式解析 (Glossary & Formulas)

1. **N-gram**: 由 $N$ 个连续 token（词或子词）组成的序列。
    
2. **Markov Assumption (马尔可夫假设)**: 假设未来状态只与当前状态（或最近的有限状态）有关，而与更早的历史无关。
    
3. **Maximum Likelihood Estimation (MLE, 最大似然估计)**: 一种直接依靠样本观测数据中事件发生的频率来估计概率的方法。这种方法在未见过的组合上会给出绝对的 0 概率（这也是后续小节需要引入平滑/Smoothing的原因）。
    
4. **Relative Frequency (相对频率)**: $C(A,B)$ 在所有 $C(A)$ 中所占的比例。

## chapter 3.2 perplexity

本节详细介绍了现代大语言模型（LLM）与传统 N-gram 模型最核心的内在评估指标（Intrinsic Metric）—— **困惑度（Perplexity, PPL）**。困惑度本质上是模型对测试集分配的概率的逆（取倒数），并根据序列长度进行归一化。本节强调了一个核心概念：一个好的语言模型对真实的测试语料会感到“更不困惑”（即分配更高的预测概率），因此其 **PPL 值越低越好**。此外，本节还从信息论的角度，将困惑度直观地解释为语言的**加权平均分支数（Weighted Average Branching Factor）**。

---

### 💡 教师重点复述 (Teacher's Emphasis)

- **重点：困惑度与概率呈反比，越低越好 (Page 46)**
    
    - **直观理解**：在阅读测试集时，如果你（模型）觉得下一步出现的词在你的意料之中（你之前给它分配了高概率），说明你不觉得困惑（Perplexity 低）。反之，如果出现的词你认为概率极低，你就会感到非常“困惑”（Perplexity 高）。
        
    - **数学本质**：由于几十个词的长句子的连乘概率必定极小，无法直接跨长度比较，所以我们要按照总词数 $N$ 开 $N$ 次方根（即取几何平均），将它变成一个**“每个词的平均得分”（Per-word metric）**。
        
- **注意：比较 PPL 时的严苛前提 (Page 47)**
    
    - **常见错误**：绝不能用含有测试集的模型来计算 PPL（即上一节强调的数据污染），否则 PPL 会虚低。另外，**两个模型比较 PPL 时，必须使用完全相同的词表（Vocabulary）！** 词表如果不同，整个概率空间就不同（小词表的模型天然给出的概率大），此时比较 PPL 就像比较苹果和橘子，毫无意义。
        
- **细节防坑：句首 `<s>` 与句末 `</s>` 的处理规则 (Page 47 脚注)**
    
    - **工程细节**：在计算测试集总词数 $N$ 时，我们要把 `</s>`（句末标记）算作一个有效词，但**不包括** `<s>`（句首标记）。因为 `</s>` 到下一句的 `<s>` 的转移概率必定趋近于 1，将其计入会稀释掉真实的困惑度评估。
    - 核心考点：总词数 $N$ 到底怎么算？(The Count of N)
		- **原文对应**：_If we do, then we also include one token per sentence in the total count of word tokens N._
		    
		- **为什么这是大坑**：困惑度 PPL 的公式是 $P(\text{整个序列})^{-\frac{1}{N}}$。这里的 $N$ 是我们要用来求几何平均的分母，**$N$ 算错了，PPL 就全错了**。
		    
		- **规则详解（结合教材脚注 2）**：
		    
		    - 句子中真实的单词，每个算 1 个 token。
		        
		    - **句末标记 `</s>`（或 `<EOS>`）要算入 $N$（每句 +1）**，因为模型确实需要预测什么时候结束这句话。
		        
		    - **句首标记 `<s>` 绝对不能算入 $N$**！为什么？因为 `<s>` 是我们人为硬塞进去作为历史上下文的开头，模型不需要去预测 `<s>` 的出现（给定上一句结束，下一句开头必定是 `<s>`，概率为 1）。如果把它加进 $N$ 里，会无端把 $N$ 变大，从而导致计算出的 PPL **虚低**（显得模型比实际表现好）。
		        
		    - **结论**：正如原文所说，每有一个句子，总词数 $N$ 只需要额外加 **1**（代表那个 `</s>`）。

### 📖 按章节详细讲解 (Section-by-Section Breakdown)

#### 1. 困惑度公式与推导 (Eq 3.14 - 3.17, Page 46-47)

- 给定一个包含 $N$ 个词的测试集序列 $W = w_1 w_2 ... w_N$。
    
- **基本定义**：测试集联合概率的倒数开 $N$ 次方。
    
    $$Perplexity(W) = \sqrt[N]{\frac{1}{P(w_1 w_2 ... w_N)}}$$
    
- 利用链式法则（Chain Rule）展开后，相当于每个词的条件概率的倒数的几何平均：
    
    $$Perplexity(W) = \sqrt[N]{\prod_{i=1}^{N}\frac{1}{P(w_i|w_1...w_{i-1})}}$$
    
- **对应 Bigram 模型**：如果使用了马尔可夫假设只看前一个词，公式即简化为：
    
    $$Perplexity(W) = \sqrt[N]{\prod_{i=1}^{N}\frac{1}{P(w_i|w_{i-1})}}$$
    

#### 2. 不同模型的 PPL 实例对比 (Page 47)

- 书中列举了在《华尔街日报》(WSJ) 的 150 万词测试集上的经典实验。使用完全相同的训练集和词表：
    
    - **Unigram 模型**: PPL = 962
        
    - **Bigram 模型**: PPL = 170
        
    - **Trigram 模型**: PPL = 109
        
- **结论**：N-gram 阶数越高，模型能利用的历史上下文就越多，因而预测得越准（赋予正确词的概率越高）。反映在指标上就是**困惑度呈显著下降**。
    

#### 3. 困惑度的物理意义：加权平均分支数 (Section 3.3.1, Page 47-48)

- **分支因子 (Branching Factor)**：在任何时刻可以合法跟在后面的候选词数量。
    
- **极简语言思维实验**：假设一门语言只有 3 个词（红、蓝、绿）。
    
    - **情况 A（毫无头绪，完全随机）**：模型认为 3 个词出现的概率均为 $1/3$。对于长度为 5 的测试序列，计算出的 $PPL = ( (1/3)^5 )^{-1/5} = 3$。这里的 PPL 刚好等于词表大小。
        
    - **情况 B（有明确偏好的模型）**：假设模型非常确定通常是红色，其概率分布为：P(红)=0.8, P(蓝)=0.1, P(绿)=0.1。此时出现测试序列 "红 红 红 红 蓝"。计算出的 $PPL = (0.8^4 \times 0.1)^{-1/5} \approx 1.89$。
        
- **直观理解**：尽管词表大小依然是 3，但因为模型对分布非常笃定，所以它的**有效加权分支数**减小到了 1.89。这就是为什么“PPL=109”可以直接理解为：**模型在生成下一个词时，感觉就像是在 109 个（等概率的）候选项里做抛硬币选择。**

### 🔤 专有名词解析 (Glossary)

1. **Perplexity (困惑度 / PPL)**: 基于信息论中交叉熵（Cross-entropy）衍生出的指标，是评估所有自回归语言模型（包括 GPT 等现代 LLM）的黄金内在指标。值越低代表预测越准。
    
2. **Weighted Average Branching Factor (加权平均分支因子)**: 困惑度的直观解释，表示模型做决策时实际面临的平均有效候选路径数量。

### 📝 配套例题与思考题 (Exercises)

1. **概念辨析**：你的团队训练了两个大模型，模型A的词表大小为 10,000 词，测试集 PPL 为 150。模型B为了涵盖更多罕见词，将词表扩充到了 50,000 词，跑出来的测试集 PPL 为 200。老板说模型 A 更好，因为 150 < 200。老板对吗？
    
    _答：不对。较小的词表（模型A）天生会使得分母变小，从而让词表内每个词分到的概率变大，导致 PPL 虚低。这在信息论中是不公平的。比较不同模型的 PPL，**必须严格确保两者的测试集和分词器（Tokenizer/词表）完全一致**。_
    
2. **手算 PPL (结合书中 Section 3.3.1)**：假设测试集是 "A B"，模型预测 $P(A) = 0.5$, $P(B|A) = 0.2$。如果不考虑句首句末标记，这个长为 2 的测试集的困惑度是多少？
    
    _答：根据公式，概率连乘为 $0.5 \times 0.2 = 0.1$。$PPL = (0.1)^{-\frac{1}{2}} = \sqrt{10} \approx 3.16$。_
## chapter3.6

### 📝 核心摘要 (Course Overview)

本节（3.6）重点解决了 N-gram 模型中的**零概率问题 (Zero-frequency Problem)**：即由于训练语料有限，测试集中必然会出现模型没见过的词组搭配，导致整个句子的连乘概率直接归零。为了解决这个问题，本节引入了**平滑 (Smoothing / Discounting)** 技术，其核心思想是“劫富济贫”——从高频事件中削减出一部分概率质量，分给未见过的事件。本节详细讲解了四种经典的平滑/回退方法：**Laplace (加一) 平滑**、**Add-k 平滑**、**插值法 (Interpolation)** 以及在大数据时代极为高效的**简单回退法 (Stupid Backoff)**。

---

### 💡 教师重点复述 (Teacher's Emphasis)

- **重点：为什么必须做平滑？(Page 51)**
    
    - **直观理解**：语言的创造性是无限的。如果你的模型没见过 `ruby slippers` 这个词组，它的概率就是 0。在连乘效应下，整个句子的概率变成 0。更致命的是，在评估模型时，**如果测试集概率为 0，困惑度 (Perplexity) 就需要除以 0，导致计算直接崩溃！**
        
- **注意：Laplace (Add-one) 平滑的致命缺陷 (Page 52-53)**
    
    - **常见错误**：很多同学在作业中喜欢用加一平滑，因为它最简单。但这在真实的 N-gram 语言模型中**效果非常差**。由于未见过的组合 (Zeros) 数量极其庞大（词表大小 $V$ 的平方或三次方），强行给每个零频词加 1，会把大量的概率空间从真实出现过的词组那里“抢走”（Discount rate 过大）。教材中举例提到，原本出现 608 次的搭配在平滑后等效于只出现了 238 次，概率被严重扭曲。_(注：但在文本分类任务中，Laplace 依然是一个好用的 baseline)_。
        
- **工程重点：Stupid Backoff (简单回退) 的暴力美学 (Page 54-55)**
    
    - **为什么重要**：传统的平滑算法（如 Kneser-Ney）需要极其复杂的概率折扣计算以保证总和为 1。但在现代海量数据（如 Web 级别的大模型预训练前身）下，Google 发现**直接放弃让概率总和为 1**，采用简单的 Stupid Backoff 算法（找到就用，找不到就退一阶并乘以固定系数 0.4），既快又能达到极其出色的工程效果。

### 📖 按章节详细讲解 (Section-by-Section Breakdown)

#### 1. 零概率问题与平滑引入 (Section 3.6, Page 51)

- **Zeros (零概率)**：出现在测试集但未出现在训练集的词序列。
    
- **Smoothing / Discounting (平滑/折扣)**：通过将一部分概率质量（Probability mass）从已见事件转移到未见事件上的算法。
    

#### 2. Laplace 平滑 (加一平滑) (Section 3.6.1, Page 51-53)

- **原理**：将所有 N-gram 的频数强行加 1。为了保证所有概率的总和仍为 1，分母必须加上词表的大小 $V$。
2. 为什么分子要 `+1`？（无中生有）

	如果我们的测试集里出现了 `eat shoe`（吃鞋子），但在训练集里这个词组出现了 0 次。
	
	如果不加 1，分子是 0，概率就是 0，整个句子的连乘也就全毁了。
	
	所以，拉普拉斯（Laplace）提出了一个简单粗暴的办法：**我们假装世界上所有的词汇组合，都比实际情况多出现了一次。**
	
	所以，分子变成了 $C(w_{n-1}w_n) + 1$。即使原本是 0 次，现在也变成了 1 次。

#### 3. 核心难点：为什么分母要 `+V`？（为了还债）

在概率论中，有一个绝对不能打破的铁律：**所有可能分支的概率总和必须等于 1**。

也就是说，在给定前一个词是 `eat` 的情况下，后面跟词表里所有词的概率加起来，必须是 100%。

现在我们来算一笔账：

假设我们的**整个词表（Vocabulary）大小是 $V$**，里面有 10,000 个单词。

因为我们在第 2 步规定：“所有可能的词汇组合，都假装多出现了一次”。

这意味着，在 `eat` 这个词后面，可能跟着 `apple`、`banana`、`shoe`、`the`……总共有 $V$（10,000）种可能的后续词。

我们给这 10,000 个可能的分支，**每一个的分子都强行加了 1**。

那么，我们总共“凭空捏造”出了多少个词的频数？

答案是：**$1 \times V = V$ 个**。

既然我们在分子上总共多出了 $V$ 次虚拟的发生次数，为了让“概率总和等于 1”的铁律不被打破，我们的**总基数（分母）也必须同步增加 $V$**。这就是为什么分母是 $C(w_{n-1}) + V$。
    
- **Bigram 公式** (Eq 3.26)：
    
    $$P_{Laplace}(w_n|w_{n-1}) = \frac{C(w_{n-1}w_n) + 1}{C(w_{n-1}) + V}$$
    
- **Adjusted Count (调整后频数)** (Eq 3.27)：为了直观看出平滑对原有频数的影响，我们可以反推出平滑后的“等效频数” $C^*$：
  在自然语言处理中，我们引入“调整后频数”（Adjusted Count, $C^*$）的目的，是为了**直观地对比平滑前后的频数变化**，看看平滑算法到底从原本的词组那里“抢走”了多少频数。
  现在，我们提出一个脑洞：

	我们能不能**不改变原始的计算公式（即分母依然保持 $C(w_{n-1})$ 不变）**，而是直接把分子替换成一个**“假的、调整过的频数” $C^*$**，让它算出来的概率，刚好等于 Laplace 平滑后的概率？
	
	用数学语言表达就是，我们希望找到一个 $C^*$，使得：![[Pasted image 20260222142445.png]]
	既然等式右边我们已经知道了，把它代入进去：

$$\frac{C^*(w_{n-1}w_n)}{C(w_{n-1})} = \frac{C(w_{n-1}w_n) + 1}{C(w_{n-1}) + V}$$

现在，只要把等式左边的分母 $C(w_{n-1})$ **乘到等式右边去**，我们就得到了 $C^*$ 的最终表达式：
    
    $$C^*(w_{n-1}w_n) = \frac{[C(w_{n-1}w_n) + 1] \times C(w_{n-1})}{C(w_{n-1}) + V}$$
    
    (你会发现高频词的等效频数锐减，这被称为 Discounting)。
    

#### 3. Add-k 平滑 (Section 3.6.2, Page 53-54)

- **原理**：既然加 1 太多了，那我们就加一个小于 1 的分数 $k$（例如 $k=0.01$）。
    
- **公式** (Eq 3.28)：
    
    $$P_{Add-k}(w_n|w_{n-1}) = \frac{C(w_{n-1}w_n) + k}{C(w_{n-1}) + kV}$$
    
- **局限**：虽然比加一平滑好，但需要用验证集（Devset）去寻找最优的 $k$，且对于语言模型来说，效果依旧不够理想。
    

#### 4. 插值法 (Interpolation) (Section 3.6.3, Page 54)

- **核心直觉**：如果没见过 Trigram（三元），Bigram（二元）和 Unigram（一元）的概率依然能提供非常有价值的线索。
    
- **线性插值 (Linear Interpolation)** (Eq 3.29)：将各阶概率按权重 $\lambda$ 加权求和：
    
    $$\hat{P}(w_n|w_{n-2}w_{n-1}) = \lambda_1 P(w_n) + \lambda_2 P(w_n|w_{n-1}) + \lambda_3 P(w_n|w_{n-2}w_{n-1})$$
    
    _(前提：所有 $\lambda$ 之和必须等于 1)_。
    
- **条件插值 (Context-conditioned weights)** (Eq 3.30)：更高级的做法是，让 $\lambda$ 随着上下文的频数变化。如果上下文很常见，就给高阶模型更大的权重。为了实现上面这种智能的权重分配，公式 3.30 将原本固定的常数 $\lambda$，变成了一个**以上下文词组为自变量的函数 $\lambda(w_{n-2}w_{n-1})$**：

$$\hat{P}(w_n|w_{n-2}w_{n-1}) = \lambda_1(w_{n-2}^{n-1})P(w_n) + \lambda_2(w_{n-2}^{n-1})P(w_n|w_{n-1}) + \lambda_3(w_{n-2}^{n-1})P(w_n|w_{n-2}w_{n-1})$$

_(注：书里的 $w_{n-2}^{n-1}$ 就是 $w_{n-2}w_{n-1}$ 的简写，即前面两个词的上下文组合)_
它在告诉计算机：**“在你分配 $\lambda_1, \lambda_2, \lambda_3$ 这三张信任票之前，请先去查一下 $w_{n-2}w_{n-1}$ 这个上下文在训练集里出现了多少次（频数）。如果它出现得多，就把 $\lambda_3$ 调大；如果它出现得少，就把 $\lambda_3$ 调小，把 $\lambda_2$ 或 $\lambda_1$ 调大。”**
    
- **如何求解 $\lambda$**：必须在一个单独保留出来的**验证集 (Held-out corpus)** 上，使用 EM (Expectation-Maximization) 算法来学习出使得验证集概率最大的 $\lambda$。
    

#### 5. 简单回退法 (Stupid Backoff) (Section 3.6.4, Page 54-55)

- **原理**：不进行复杂的概率融合，而是按层级“回退”。如果高阶存在，直接用高阶；如果高阶计数为 0，就回退到低阶，并施加一个固定的惩罚系数 $\lambda$（通常设为 0.4）。

### 🔤 专有名词与公式解析 (Glossary)

1. **Discounting (折扣)**: 为了给未登录词腾出概率空间，算法会系统性地“削减”已登录高频词的概率或频数，这个削减过程叫做 Discounting。
    
2. **Held-out Corpus (保留语料库)**: 为了学习平滑算法中的超参数（如 Interpolation 中的 $\lambda$ 权重）而从训练集中单独切分出的一小块数据集。
    
3. **Backoff vs. Interpolation (回退与插值的区别)**: 插值法是**无论如何都会把所有阶数的概率混合**起来；而回退法是**只有在找不到高阶搭配时，才退而求其次**使用低阶。

### 💻 算法伪代码与可运行建议 (Code Implementation)

以下是在 Python 中实现 **Interpolation (插值)** 和 **Stupid Backoff** 的核心逻辑：

Python

```
class NgramSmoothing:
    def __init__(self, unigram_probs, bigram_probs, trigram_probs):
        self.p1 = unigram_probs
        self.p2 = bigram_probs
        self.p3 = trigram_probs
        
    def linear_interpolation(self, w_n, w_n1, w_n2, lambdas=(0.1, 0.3, 0.6)):
        """Eq 3.29 线性插值"""
        l1, l2, l3 = lambdas
        # 提取不同阶的概率，若不存在则为0
        prob1 = self.p1.get(w_n, 0)
        prob2 = self.p2.get(w_n1, {}).get(w_n, 0)
        prob3 = self.p3.get(w_n2, {}).get(w_n1, {}).get(w_n, 0)
        
        return l1 * prob1 + l2 * prob2 + l3 * prob3
        
    def stupid_backoff(self, w_n, w_n1, w_n2, discount=0.4):
        """Eq 3.31 简单回退"""
        # 尝试 Trigram
        if w_n in self.p3.get(w_n2, {}).get(w_n1, {}):
            return self.p3[w_n2][w_n1][w_n]
            
        # 回退到 Bigram
        if w_n in self.p2.get(w_n1, {}):
            return discount * self.p2[w_n1][w_n]
            
        # 回退到 Unigram (终止条件)
        # 注意实际计算时这里应该是 count(w_n) / N
        return (discount ** 2) * self.p1.get(w_n, 1e-10)
```

3. **工程思考 (Stupid Backoff)**：
    
    为什么在大规模（如万亿词级）语料下训练语言模型时，Google 研究员会倾向于选择 Stupid Backoff 而不是数学上更严谨的 Kneser-Ney 平滑？
