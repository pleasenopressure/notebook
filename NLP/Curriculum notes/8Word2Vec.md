## 🚨 教师重点复述 (考试与实践高频考点)

老师在课堂上反复强调了以下几点，请务必作为重点复习：

1. **张量形状 (Tensor Shapes) 的理解**：老师明确表示，**如果他是考官，一定会考文本到张量的转换过程** 。在实际使用 PyTorch 时，张量形状不匹配是最常见的错误 。你必须熟练掌握输入向量、批量 (Batch) 以及词嵌入矩阵乘法前后的维度变化（详见下文图解） 。
2. **千万不要用全 0 初始化权重！** 教授特意提问并解答：训练开始时，嵌入矩阵绝对不能用全 0 或全 1 初始化，否则会彻底破坏训练，导致模型什么都学不到 。必须使用高斯噪声（Gaussian noise）进行随机初始化 。
3. **为什么现在不怎么去除“停用词 (Stopwords)”了？** 传统 NLP 喜欢去掉 "the", "and" 这样的词以浓缩信息。但教授指出，现在的 GPU 算力足够强大，而停用词在下游任务（如心理健康分析）中往往包含极其重要的语境信息 。去除它们反而会破坏上下文的完整性。
4. **工程优化：丢弃一半的矩阵**  训练 Word2Vec 时，我们维护了一个巨大的矩阵（目标词矩阵 $W$ + 上下文矩阵 $C$，总大小为 $d \times 2|V|$） 。但在训练完成后，工程界的标准做法是**直接丢弃下半部分（$C$ 矩阵）**，只保留 $W$ 矩阵，这样不仅性能不变，还能节省一半的显存 。
5. **静态 (Static) vs 上下文 (Contextual) 词嵌入**：必须能区分两者的概念。Word2Vec 是静态的（同一个词在任何句子里向量都一样），而 BERT、GPT 等是上下文相关的（同一个词由于上下文不同，向量也会动态变化） 。
6. **算法偏见 (Bias in Embeddings)**：老师对于“下一代 AI 工程师”寄予厚望，花了大量篇幅强调偏见问题 。务必理解**分配伤害 (Allocation harm)** 和**表象伤害 (Representational harm)** 的区别，并了解如何通过声明“数据卡 (Data Card)”来缓解和提示偏见风险 。

## 📖 按章节详细讲解

#### 1. 词嵌入基础与 Skip-gram 模型 

- **自监督学习**：Word2Vec 不需要人工标注的数据（如词性标注），它直接利用海量未标注文本进行训练 。训练的代理任务是“预测单词 A 是否可能出现在单词 B 附近”，但我们真正想要的是训练结束后提取出来的权重矩阵（即词嵌入） 。
	  - **核心逻辑**：**有目标标签（Has Labels），但标签是数据自己“免费”提供的。** 我们不需要花钱雇人去给数据打标签（比如标出哪些词是名词、哪些句子带有负面情绪），而是通过设计一个**“代理任务 (Pretext Task)”**，让数据的一部分去预测另一部分。
	    
	- **数学视角**：模型进行的是标准的监督学习操作，即通过输入 $x$ 预测输出 $y$。但是！这里的 $y$ 是算法直接从原始无标注数据 $X$ 中自动截取出来的。
	    
	- **经典例子**：
	    
	    - **Word2Vec (本节课)**：原始句子是“apricot jam” 。我们不需要人工标注任何东西。算法自动把“apricot”当作输入 $x$（目标词），把“jam”当作标签 $y$（正样本上下文词）来进行分类器训练 。
	        
	    - **BERT (掩码语言模型)**：给你一句话“我今天去吃火锅”，把“吃”字遮住（Mask），让模型去猜被遮住的字是什么。这里的“吃”就是数据自身提供的标签。
- **Skip-gram 任务**：给定一个目标词 (Target word)，预测它周围的上下文词 (Context words) ，目标词及其邻近词构成正样本，通过随机抽样生成负样本，使用逻辑回归训练分类器 。
    - **数学建模**：模型使用逻辑回归来计算概率，使用点积衡量目标词 $w$ 和上下文词 $c$ 的相似度，并通过 Sigmoid 函数 $\sigma(x)$ 将其转化为概率 。
    - 正样本概率：$P(+|w,c)=\sigma(c\cdot w)=\frac{1}{1+exp(-c\cdot w)}$
    - 负样本概率：$P(-|w,c)=1-P(+|w,c)=\sigma(-c\cdot w)$

    - **独立性假设**：假设所有上下文词是独立的，因此可以将整个窗口 $L$ 的概率相乘 。
    
	- **双矩阵结构**：模型实际上维护了两个矩阵：目标词矩阵 $W$ 和上下文/噪声词矩阵 $C$ 。词向量维度 $d$ 的大小是通过实验经验得出的 。
	    ![[Pasted image 20260301133825.png]]
	- **负采样 (Negative Sampling)**：为了避免对常见词的严重偏见，在抽取负样本（噪声词）时，使用加权的一元语法样本频率 $P_{\alpha}(w)$ 。
#### 为什么Skip-gram任务训练阶段需要维护两个矩阵，而部署阶段却要抛弃C矩阵
##### 1. 训练阶段：为什么需要“自由度”？（为了给优化器松绑）

假设我们强行只用一个矩阵 $W$。当窗口里出现了重复词（比如句子是 "apple is apple"），模型要用中心词 "apple" 去预测上下文词 "apple"。

- 如果只用一个矩阵，你要计算的点积就是 $w \cdot w$。在线性代数中，一个向量与自己的点积必定是它**长度的平方**（一个严格非负的数）。
    
- 这等于给多维空间中的梯度下降（SGD）套上了一个极其死板的“几何枷锁”。优化器在调整这个词的向量时，不仅要顾及它和别的词的距离，还要被迫受制于“它和自己点积必须非负且等于模长平方”的硬性约束，这很容易让损失函数陷入局部最优，难以收敛。
    
- **拆分 $W$ 和 $C$ 的意义在于**：$w \cdot c$ 可以是任何值（正、负、零）。模型在多维空间里推拉这些向量时，没有任何死板的自身约束。这种“解耦”是**数学和工程技巧**上的需要，是为了让梯度下降走得更顺滑。
    

##### 2. 收敛阶段：为什么结果会“冗余”？（因为数据的对称性）

虽然我们在数学上给了 $W$ 和 $C$ 完全自由的发展空间（甚至让它们随机初始化），但**喂给它们的数据（人类语言）是高度对称的**。

- 在海量语料中，如果 "apricot" 经常作为 "jam" 的中心词出现，那么反过来，"jam" 也必然经常作为 "apricot" 的中心词出现。
    
- 因为数据的这种对称性，负责“目标词”的 $W$ 矩阵和负责“上下文”的 $C$ 矩阵，虽然一开始各走各的，但在千百万次的梯度更新后，它们**被迫学习到了同一套语言规律**。
    
- 结果就是：$W$ 空间和 $C$ 空间最终对齐了。它们并没有变成完全一模一样的矩阵（因为初始化不同，且 SGD 有随机性），但它们所编码的“语义信息”高度重合（冗余）了。
    

##### 3. 部署阶段：为什么放心丢弃 $C$？（工程上的性价比）

既然 $W$ 和 $C$ 殊途同归，学到了极其相似的语义信息，那么在实际应用中：

- 如果把 $W$ 和 $C$ 拼接在一起使用，你花费了 200% 的内存，但由于信息高度冗余，可能只获得了 101% 的语义增益。这在工程上是极不划算的。
    
- 当然，正如课件 Slide 12 所指出的，为了榨干最后一丝信息，有时候研究人员也会将词嵌入矩阵定义为 $W + C$ （按位相加，既融合了两者微小的视角差异，又没有增加维度），或者像工业界最常见的做法那样，“有时候仅仅使用 $W$” 。
##### 助教的比喻

想象有两台不同的摄像机（$W$ 和 $C$）在拍同一场舞台剧。

- 如果硬要把两台摄像机绑在一起（一个矩阵），摄影师会互相绊脚，很难拍出好画面（优化困难）。
    
- 我们把它们拆开，各自找角度拍（数学上的解耦和自由度）。
    
- 但因为拍的是同一场戏（语言的对称性），最后两台摄像机拍出来的录像（语义信息）是高度相似的（冗余）。
    
- 到了最后剪辑播出时（部署推理），导演发现只放第一台摄像机（$W$ 矩阵）的画面已经完全够清晰了，为了省胶片，干脆就把第二台的录像扔了。

#### 2. 负采样与损失函数 (Slide 7-12 / Transcript 12:47-22:20)

- 为了提高训练效率，我们不仅需要正样本（实际出现在滑动窗口内的词），还需要引入**负样本 (Negative examples)**，即从词表中随机抽取的、不与目标词相邻的词 。
    
- **词频降权**：为了防止模型对“the”、“and”等高频停用词过拟合，采样负样本时会使用加权的一元语法频率 (weighted unigram sample frequency) 。
  $$P_{\alpha}(w)=\frac{count(w)^{\alpha}}{\sum_{w^{\prime}}count(w^{\prime})^{\alpha}}$$
    
- **损失函数优化**：模型通过随机梯度下降 (SGD) 最小化交叉熵损失。训练的直观目的是：**在向量空间中，把目标词拉近正样本上下文词，推远负样本词** 。
##### 1. 为什么需要“负采样”？

在 Skip-gram 模型中，我们想要训练一个目标词（比如“apricot/杏子”）和它的真实上下文词（比如“jam/果酱”）。为了让分类器起作用，我们不仅要给它**正样本**（告诉它 apricot 和 jam 相关），还要给它**负样本**（告诉它 apricot 和某些“噪声词”不相关，比如 matrix/矩阵） 。

如果我们要找负样本，最直接的想法就是从整个词典里**随机盲抽**。

##### 2. 为什么不能直接按“真实词频”随机抽？（引入问题的关键）

在自然语言中，词频的分布是极其不均匀的（符合齐夫定律）。像 "the", "a", "is", "of" 这样的停用词，出现的频率极高；而像 "aardvark"（土豚）或 "apricot" 这样的词频率很低。

如果我们完全按照词在语料库中的**真实频率**去抽取负样本，会发生什么？

- 你的负样本里几乎 90% 都是 "the", "is", "a"。
    
- 模型会疯狂地学习“apricot 和 the 不相关”、“apple 和 the 不相关”……
    
- **结果（偏见）**：模型为了降低损失函数，会把所有的精力都花在推远 "the" 这样的常见词上，而对于那些真正有意义但相对罕见的词（比如抽到 "matrix" 作为负样本的概率极低），模型根本学不到它们之间的区分度 。
    

##### 3. 加权的一元语法样本频率 $P_{\alpha}(w)$ 是如何解决这个问题的？

为了“避免对常见词的严重偏见” ，研究人员对词频的概率分布动了手脚。公式如下：

$$P_{\alpha}(w)=\frac{count(w)^{\alpha}}{\sum_{w^{\prime}}count(w^{\prime})^{\alpha}}$$

这里的核心魔法在于指数 $\alpha$（在 Word2Vec 的标准实现中，$\alpha$ 通常被设定为 **0.75**，即 $3/4$）。

- 如果 $\alpha = 1$：那就是**真实概率**分布（高频词绝对霸权）。
    
- 如果 $\alpha = 0$：所有的 $count(w)^0$ 都等于 1，这就变成了**完全均匀分布**（不管 "the" 还是 "apricot"，被抽成负样本的概率完全一样）。
    
- **当 $\alpha = 0.75$ 时**：这是一个折中方案。它起到了**“打压高频词，提携低频词”**的平滑作用。
#### 3. One-hot 编码与张量维度

- **词表构建**：首先为词汇表中的每个词分配一个整数索引。必须包含一个 `<UNK>` (Out Of Vocabulary) 标记来处理未见过的词，以及在处理批数据时使用的 `<PAD>` (Padding) 标记 。
    
- **形状变化示例** (假设词表大小 $|V| = 11$，嵌入维度 $d$)：
    
    - **单个词的 One-hot 向量**：张量形状为 $1 \times 11$ 。
        
    - **单个句子的 One-hot 矩阵** (假设句子有 4 个词)：形状为 $4 \times 11$ 。 
    
    - **单个词的词嵌入提取**：输入向量 $1 \times 11$ 乘以嵌入矩阵 $11 \times d$，输出维度为 $1 \times d$ 。注意“嵌入维度（Embedding Dimension，通常用 $d$ 表示）”并不是 $|V|$，而是我们希望把这个词“压缩/映射”到的目标稠密向量的长度。
        
    - **批处理 (Batched)**：在工程应用中，为了 GPU 加速通常会引入 Batch。如果 Batch size 为 32，句子长度为 4，词汇表为 11，则输入的张量形状将变为 $32 \times 4 \times 11$ 。

#### 4. 语义特性分析 

- **上下文窗口大小 ($L$) 的影响**：
    
    - 较小的 $L$ (如 2-4) 捕捉**相似性 (Similarity)**（例如“青蛙”和“老鼠”在语法和类别上的相似） 。
    - 较大的 $L$ (如 5+) 捕捉**主题关联性 (Association)**（例如“霍格沃茨”与“邓布利多”、“马尔福”的关联） 。

- **词向量类比**：通过向量偏移计算。例如，国王 - 男人 + 女人 $\approx$ 女王 。
#### 不同的经典模型选择

- **FastText (Facebook)**：使用子词（Subword units / character n-grams）。**优势**：非常擅长处理拼写错误（typos）和生僻词 。
#####  1. 传统 Word2Vec 的致命弱点

在标准的 Word2Vec 中，每一个词都被看作一个**不可分割的原子实体**。

比如 "play"、"plays"、"playing" 在词表中是三个完全独立、互相没有联系的索引编号。如果你在训练时只见过 "play"，而在实际应用时遇到了 "playing"，Word2Vec 只能两手一摊，把它当成未知的 `<UNK>`（未登录词）处理。这个适合解决解决 OOV（Out Of Vocabulary，未登录词）和罕见词问题以及捕获形态学信息（词根与词缀）。

##### 2. 子词与字符 n-gram 的运行原理

FastText 打破了“词是最小单位”的限制，它深入到了**单词的内部（字符级别）**。

- **步骤 A：拆解词汇 (Breakdown)**
    
    假设我们设定 $n=3$（即 3-gram，每次取3个字符），并在单词的前后加上特殊的边界符号 `<` 和 `>` 以区分词首和词尾。
    
    以单词 **"where"** 为例，它会被拆解成以下 3-gram 的集合：
    
    - `<wh`
        
    - `whe`
        
    - `her`
        
    - `ere`
        
    - `re>`
        
    - _外加整个单词本身：_ `<where>`
        
- **步骤 B：向量计算 (Vector Calculation)**
    
    在模型底层，我们不再只是维护一个“词”的权重矩阵，而是维护一个庞大的**“子词”权重矩阵**。
    当我们需要获取 "where" 的词向量时，模型会去查找上述所有子词（`<wh`, `whe`, `her`...）各自的向量，然后**将这些子词向量相加（求和）**，最终得出的结果就是 "where" 的词向量

- **GloVe (Stanford)**：包含高达 130,000 的词表，曾在 Twitter 等多种语料上训练。**优势**：如果你要处理社交媒体文本，直接拿它来用效果很好 。
#### 5. 其他静态嵌入与伦理偏见 
- 除了 Word2Vec，还有使用字符 n-gram 解决生僻词问题的 **FastText**，以及基于全局共现矩阵的 **GloVe** 。
- **算法偏见**：模型会编码训练数据中固有的历史偏见（如性别偏见：男人->程序员，女人->家庭主妇） 。
    - **Allocation harm (分配伤害)**：算法导致现实世界中不公平的结果（如简历筛选或执法画像） 。
    - **Representational harm (表象伤害)**：系统贬低或无视某些社会群体（如聊天机器人输出冒犯性言论） 。

## 💻 工程实践：PyTorch 伪代码示例

为了帮你应对老师关于“张量形状”的考察，这里展示如何用 PyTorch 实现这段逻辑。

Python

```
import torch
import torch.nn as nn

batch_size = 32
seq_length = 4
vocab_size = 11  # |V|
embedding_dim = 100 # d

# 1. 模拟一个批次的 Token IDs (通常我们不直接传入One-hot进行矩阵乘法，而是用nn.Embedding查表，这在底层等价)
# 张量形状: (batch_size, seq_length) -> (32, 4)
input_ids = torch.randint(0, vocab_size, (batch_size, seq_length))

# 2. 定义词嵌入层
# 相当于定义了大小为 |V| x d 的矩阵 W
embedding_layer = nn.Embedding(num_embeddings=vocab_size, embedding_dim=embedding_dim)

# 3. 获取词向量
# 输入形状: (32, 4)
# 输出形状: (32, 4, 100) -> 对应 (batch_size, seq_length, embedding_dim)
embeddings = embedding_layer(input_ids)

print(f"Input shape: {input_ids.shape}")
print(f"Output embedding shape: {embeddings.shape}")
```
