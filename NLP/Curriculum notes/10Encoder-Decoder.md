## 📌 课程精炼摘要 (1分钟速览)

本节课重点讲解了**序列到序列（Seq2Seq）任务**在机器翻译中的应用 。传统的 RNN 编码器-解码器模型会将整个输入压缩成一个固定长度的**上下文向量（Context Vector）**，但这在处理长文本时容易遗忘早期信息 。引入**注意力机制（Attention）后，解码器能在生成每个词时“动态查阅”源文本的不同部分，从而大幅提升翻译质量 。此外，课程还对比了贪婪搜索（Greedy Search）**与**束搜索（Beam Search）**的优劣 ，并深入实战了机器翻译的评价指标（如 ROUGE 和 BLEU） 。

## 📖 按章节/幻灯片详细讲解

#### 1. 机器翻译与序列到序列模型 (Slide 3-5 / @0:41-8:30)

- **Seq2Seq 任务的本质**：输入和输出的序列长度通常是不相等的（$Ien(X) != Ien(Y)$） 。这种结构不仅适用于翻译，还能无缝切换到问答（QA）、关系抽取（RE）和文本摘要等任务 。
    
- **翻译的难点（词序类型学 Word Order Typology）**：不同语言的语法结构不同 。例如英语和德语多为 SVO（主谓宾），日语是 SOV（主宾谓），而阿拉伯语是 VSO（谓主宾） 。因此，模型不能逐词死板翻译，必须看完整个源句子才能决定如何生成 。
    

#### 2. Encoder-Decoder 基础架构 (Slide 6-10 / @8:34-20:56)

- **Encoder（编码器）**：负责阅读输入序列 $X$，并将其压缩成一个内部表示，即**上下文向量 $c$**（通常是编码器 RNN 的最后一个隐藏层状态 $h_n$） 。
    
- **Decoder（解码器）**：这是一个条件语言模型 。它在生成每一个目标词时，都会依赖于上下文向量 $c$、上一个时间步的隐藏状态 $h_{t-1}$ 以及上一个生成的词 $y_{t-1}$ 。
    
- **Teacher Forcing（强制教学）**：在训练阶段，为了防止误差累积，我们不会将模型上一层的错误预测喂给下一层，而是直接将**真实的标注词（Gold answers）**作为下一步的输入 。
    

#### 3. 注意力机制 Attention (Slide 11-12 / @20:56-28:33)

- **为什么要 Attention？**：基础模型中，固定长度的上下文向量 $c$ 成了信息瓶颈，且 RNN 存在遗忘问题，导致长文本翻译效果很差 。
    
- **工作原理**：Attention 允许解码器在生成每个词时，对源语言序列中的所有隐藏状态 $h_j^e$ 进行加权求和 。
    
    - **打分 (Score)**：以点积注意力为例，计算解码器当前状态 $h_{i-1}^d$ 与编码器各状态 $h_j^e$ 的点积 。
        
    - **权重分配 (Softmax)**：将分数转化为总和为 1 的注意力权重 $\alpha_{ij}$ 。
        
    - **动态上下文 (Context Vector)**：使用公式 $c_i = \sum_j \alpha_{ij} h_j^e$ 计算出专属于当前生成步的上下文向量 。
        
##### 1. 直观理解：解码器是如何“环顾四周”的？

在传统的 Seq2Seq 模型里，解码器只能捏着一个固定的上下文向量（就像记了一句死记硬背的话）去翻译，句子一长就容易忘 。

引入 Attention 后，解码器在每次要“吐出”一个新词时，都可以**回头看一眼编码器的所有单词** 。

- **点积（Dot-product）的作用是什么？** 它其实是在算**“相似度”** 。解码器拿着自己当前的状态去问编码器里所有的词：“你们谁跟我现在的状态最匹配/最相关？” 。匹配度越高的词，点积结果越大，在翻译当前词时分给它的注意力权重就越大。
    

##### 2. 数学推导与公式拆解（紧扣 PPT Slide 12）

我们假设现在解码器正在尝试生成第 $i$ 个词（当前时间步为 $i$），而源语言有 $n$ 个词（索引为 $j = 1, 2, ..., n$）。整个过程分为三大关键步骤：

**第一步：计算注意力得分 (Score)**

- **公式**：$score = h_{i-1}^d \cdot h_j^e$
    
- **含义**：解码器拿出**上一个时间步**的隐藏状态 $h_{i-1}^d$ ，分别与编码器里**每一个**词的隐藏状态 $h_j^e$ 做点积运算 。
    
- _下标避坑_：$i$ 代表解码器的进度，$j$ 代表编码器里的词的位置 。
    

**第二步：计算注意力权重 (Attention Weight) $\alpha_{ij}$**

- **公式**：$\alpha_{ij} = softmax(score)$
    
- **含义**：点积算出来的得分有大有小、有正有负。我们通过 Softmax 函数，把这 $n$ 个得分转化成一个总和为 $1$ 的概率分布 。比如针对“Bruja（女巫）”这个词的翻译，源句子里的 "witch" 可能会分到 0.8 的权重，而 "the" 和 "green" 可能只分到 0.1。
    

**第三步：计算动态上下文向量 (Context Vector) $c_i$**

- **公式**：$c_i = \sum_j \alpha_{ij} h_j^e$
    
- **含义**：将编码器中每一个词的隐藏状态 $h_j^e$，乘以刚刚算出的对应权重 $\alpha_{ij}$，然后全部加起来（加权求和） 。
    
- **结果**：这个新算出来的 $c_i$ 就是专门为生成第 $i$ 个词量身定制的“上下文线索” 。接着，模型会把 $c_i$、上一层的输出 $y_{i-1}$ 以及前一个隐藏状态一起送入解码器，来预测下一个词 。

#### 4. 解码策略：贪婪搜索与束搜索 (Slide 13-16 / @28:33-36:21)

- **Greedy Search（贪婪搜索）**：每一步都只选概率最大（argmax）的那个词 。**缺点**：极其短视，一旦前面选错一步（落入局部最优），后面就会在错误的道路上越走越远，且无法回溯 。
    
- **Beam Search（束搜索）**：在内存中同时保留 $k$ 个最有希望的生成序列（$k$ 称为波束宽度 Beam Width） 。每次扩展时，评估所有可能的后续词，然后再次筛选出前 $k$ 个最优序列 。老师推荐 $k$ 通常设为 10 左右以保证质量，代价是推理速度大幅下降 。
    
## 1. 痛点：为什么不用简单的贪婪搜索（Greedy Search）？

在学习 Beam Search 之前，我们要先明白不用它会怎样。

- **短视的贪婪**：贪婪搜索（使用 `argmax`）在每一步生成目标词时，都只挑**当前这一步**概率最大的词 。
    
- **没有“后悔药”**：解码是一条单行道。如果模型在早期分支处选错了一个词（比如把“商店 shops”预测成了“电影院 movies”），它会在错误的岔路上越走越远，完全无法回溯修正 。
    
- **错失全局最优解**：老师在 Slide 14 中给了一个极好的例子：如果只看第一步，`yes` 的概率（0.5）比 `ok`（0.2）大，贪婪搜索会毅然决然地走 `yes -> yes -> </s>` 。但如果我们往后看，`ok -> ok -> </s>` 的全局相乘概率其实更高！贪婪搜索因为第一眼的短视，陷入了“局部最优”，错过了“全局最优” 。
    

## 2. 核心原理：什么是 Beam Search？

为了解决上述问题，Beam Search 给解码器加上了“记忆”和“多头下注”的能力 。

- **波束宽度（Beam Width, $k$）**：这是模型能同时记住的候选序列（hypotheses）的数量 。
    
- **扩展与裁剪 (Expand & Prune)**：
    
    1. 在生成下一个词时，模型会把当前手里攥着的 $k$ 个候选序列，分别与庞大的词表库（假设大小为 $V$）进行组合拼接。
        
    2. 这时，模型面临着 $k \times V$ 种全新的分支可能 。
        
    3. 接着，模型会对这 $k \times V$ 个序列进行打分评估，**大浪淘沙，再次只保留总得分最高的 $k$ 个序列**，把其余的全部扔掉 。
        
    4. 重复这个过程，直到这 $k$ 个序列都生成了句子结束符 `</s>` 。
        

## 3. 🚨 助教极其强调的细节：为什么要用对数概率 (Log Probabilities)？

这是老师课上**特别强调的工程细节**，也是面试常考题！

- **连乘的灾难**：如果你把正常的概率（介于 0 到 1 之间的小数）连续相乘，一旦某个生僻词的概率是 $0$，那么整个长句子的概率就会瞬间变成 $0$，导致整个序列被毁掉 。此外，多个小数相乘在计算机底层非常容易发生“数值下溢”。
    
- **Log 技巧 (Log Trick)**：我们在代码中会取概率的对数（Log）。这样，**概率的乘法就变成了对数的加法** 。
    
- **如何比较**：因为概率是小于 $1$ 的，所以 Log 之后都是负数。我们在树状图上比较时，**负数值越接近 0，代表这个序列的概率越大**（比如老师提到的例子中，$-1.6$ 就要优于 $-9.2$） 。
    

## 4. 课件实战推演（结合 Slide 16，以 $k=2$ 为例）

为了能在一页 PPT 上画下，老师把波束宽度设为了 $k=2$ 。我们来模拟一下它的运行：

1. **起始**：模型预测第一个词，得出了两个最高分的词 `arrived` (得分 -1.6) 和 `the` (得分 -0.92)。因为 $k=2$，我们把它们都放进内存 。
    
2. **第一轮扩展**：基于 `arrived` 和 `the` 分别预测下一个词，产生了 4 个新序列。计算对数得分后，模型发现 `the green` (-1.6) 和 `the witch` (-2.1) 是得分最高的两个 。
    
3. **淘汰出局**：此时包含 `arrived` 的序列因为后续得分太低，被无情丢弃。内存里更新为 `the green` 和 `the witch` 这两条平行运行的路线 。
    
4. **最终抉择**：如此不断推进，最后模型可能会生成 `the green witch arrived </s>` 和 `the witch arrived </s>` 两个完整句，然后挑出最终总分（累加对数值）最高的那一个 。
    

## 5. 权衡取舍 (Trade-offs)

天上不会掉馅饼，使用了 Beam Search 必然要付出代价：

- **内存与计算量的暴增**：你要同时追踪多个分支，内存开销和推理延迟（Inference time）会成倍增加 。
    
- **工业界现状**：如果你追求极其快速的响应（哪怕容忍一点小错误），就用贪婪解码 ；如果你想要高质量、高精度的翻译，就必须付出时间等待，使用 Beam Search 。老师提到，实际生产环境中，为了保证优质输出，$k$ 的值往往设定在 $10$ 左右
#### 5. 训练数据与评估指标 (Slide 17-20 / @36:21-45:33)

- **反向翻译 (Backtranslation)**：因为高质量的平行语料库（Bitext）太小，通常利用大规模的单语语料库 。先用小数据训练一个“目标语言 -> 源语言”的粗略模型，然后翻译海量单语语料生成伪数据（Synthetic bitext），再混合起来训练主模型，靠着 Transformer 的大力出奇迹来抵消噪音 。
    
- **评估指标**：
    
    - **BLEU**：关注 n-gram 的精确率（Precision） 。
        
    - **ROUGE**：关注 n-gram 的召回率和重叠情况（Overlap）。其中 ROUGE-L 计算最长公共子序列 。
        
    - **BERTScore**：利用预训练语言模型计算词对的语义相似度，能容忍同义词替换（比如 shopping 换成 skydiving 语义全变，BERTScore 能查出来，但单纯的字符匹配指标会给高分） 。

## 🧠 专有名词与公式解析

- **BPE (Byte Pair Encoding)**
    
    - _解释_：一种子词标记化技术（如 WordPiece）。它通过统计高频字符对来构建词表，能有效解决机器翻译中的“未登录词（OOV）”问题，并控制词表大小在计算内存允许的范围内（如 50k） 。
        
- **Dot-product attention (点积注意力/Luong Attention)**
    
    - _打分公式_：$score = h_{i-1}^d \cdot h_j^e$
        
    - _动态上下文_：$c_i = \sum_j \alpha_{ij} h_j^e$
        
    - _直观理解_：解码器拿出当前的“疑问向量”，跟编码器的所有“记忆向量”分别做内积（相似度计算）。结果越大的，代表那个词在当前翻译步骤越重要，就分给它更多的权重。
        
- **Teacher Forcing**
    
    - _解释_：训练 Seq2Seq 模型时的一种策略 。不使用模型上一步的输出 $y_{t-1}$ 作为下一步的输入，而是强制给它塞入正确的标准答案。这能极大加快模型初期的收敛速度。

## 📝 配套例题与思考

**实战题：ROUGE 指标计算体验**（依据课件 Slide 19 模拟 ） _参考答案 (Ref)_: `[ do, I, love, NLP, worked, examples, ? ]` (总词数 = 7) _模型生成 (Gen)_: `[ examples, we, all, love, NLP, with, ? ]` **问题**：请计算 ROUGE-1 和 ROUGE-2。 **助教解析**：

1. **ROUGE-1 (1-gram)**：Gen 与 Ref 共有的单词是 `love`, `NLP`, `examples`, `?`。共计 4 个 。$ROUGE-1 = 4 / 7 \approx 0.57$ 。
    
2. **ROUGE-2 (2-gram)**：Gen 与 Ref 共有的连续双词组合只有 `love NLP`，计 1 个 。$ROUGE-2 = 1 / 6 \approx 0.16$ 。
