### 📖 3. 课程详细梳理 (Content Breakdown)

#### 3.1 什么是正则表达式？ (Basics)

- **定义**：描述字符串模式的语言。
    
- **应用场景**：比如在 500 万份法律文档中提取各种格式的电话号码 。
    
- **基本语法速查** ：
    
    +1
    
    - `\b`: 单词边界 (Word boundary)。
        
    - `\w`: 单词字符 (相当于 `[a-zA-Z0-9_]`)。
        
    - `\d`: 数字 (Digits, `[0-9]`)。
        
    - `\s`: 空白字符 (Whitespace)。
        
    - `.`: 通配符 (Wildcard)，匹配除换行外的任意字符。
        
    - `[]`: 字符集，如 `[abc]` 匹配 a 或 b 或 c。
        
    - `[^]`: 否定字符集，如 `[^A-Z]` 匹配非大写字母。
        

#### 3.2 重复操作符 (Repetition)

这是考试中容易混淆的点 ：

+1

- **`*` (Kleene Star)**: 0 次或多次。
    
- **`+` (Kleene Plus)**: 1 次或多次。
    
- **`?`**: 0 次或 1 次（可选）。
    
- **`{n,m}`**: 最少 n 次，最多 m 次。
    

#### 3.3 贪婪 vs 非贪婪 (Greedy vs Non-greedy)

- **贪婪 (默认)**：`*` 和 `+` 会尽可能多地匹配字符。
    
    - _例子_: 对于字符串 `Hooray! It's nice! Goodbye!`
        
    - 正则 `H.*!` 会从 H 匹配到**最后一个**感叹号 。
        
- **非贪婪 (Lazy)**：在操作符后加 `?` (如 `*?`, `+?`)，使其尽可能少地匹配。
    
    - _例子_: 正则 `H.*?` 会在遇到**第一个**感叹号时停止 。
        

#### 3.4 分组与捕获 (Groups)

- **捕获组 `()`**: 将一部分匹配存入内存，可以通过索引（Register）调用。
    
    - _应用_: `I am a (\w+) person, do you like \1s?` -> 如果第一个空填 cat，第二个空自动匹配 cats 。
        
- **非捕获组 `(?:)`**: 仅用于分组逻辑（如 `(red|blue)`），但不保存结果到索引中，节省内存 。
    
- **逻辑或 `|`**: `cat|dog` 匹配 cat 或 dog。注意优先级：`red|blue|green slime` 匹配的是 "red" OR "blue" OR "green slime"。如果想要 "red slime" OR "blue slime"，必须写成 `(red|blue) slime` 。
    

#### 3.5 环视断言 (Lookaround Assertions)

**高阶难点，Lab 1 必做** 。 断言匹配位置，不消耗字符（即匹配后光标不移动）。

- **正向先行断言 (Lookahead)** `(?=foo)`: 站在当前位置往右看，必须有 foo。
    
- **正向后行断言 (Lookbehind)** `(?<=foo)`: 站在当前位置往左看，必须有 foo。
    
- **负向 (Negative)**: `(?!foo)` (右边不能有), `(?<!foo)` (左边不能有)。
    
- **应用案例**：密码验证（必须包含大写、数字、长度限制，且顺序任意）需要组合多个 Lookahead 来实现 。
- 例子：
```
      match = re.search(r'(Thought:.*?Action:.*?)(?=\n\s*(?:Thought:|Action:|Observation:)|\Z)', llm_output, re.DOTALL)
```
这里实现了一个只抓取第一对Thought 和 Action，只要一旦看到下一行出现了新的Thought/Action/Observation 标志，或者到了文本末尾，就立即收手。
其中（？=）实现了前面的匹配规则每匹配上一个字符就会向后查看是否有字符符合（？=）中的内容，一旦符合由于后面没有更多的匹配规则了，匹配就会直接结束。
#### 3.6 评估指标 (Evaluation)

Regex 本质上也是一种信息检索任务，会有两类错误 ：

1. **False Positives (假阳性)**: 匹配了不该匹配的垃圾信息（精度 Precision 低）。
    
2. **False Negatives (假阴性)**: 漏掉了本该匹配的正确信息（召回 Recall 低）。

### 📚 4. 核心术语表 (Terminology)

|**术语**|**英文**|**解释**|
|---|---|---|
|**DFA**|Deterministic Finite Automaton|确定性有限自动机。Regex 的数学理论基础，保证了匹配过程是确定的。|
|**Greedy**|Greedy Matching|贪婪匹配。Regex 引擎默认尽可能多地吞噬字符（直到不满足条件为止）。|
|**Non-greedy**|Non-greedy / Lazy|非贪婪匹配。匹配满足条件的最小字符数。通常通过在 `*` 或 `+` 后加 `?` 实现。|
|**Raw String**|Raw String (`r''`)|Python 中的原始字符串。告诉解释器不要转义反斜杠，将 `\n` 视为两个字符 `\` 和 `n`，这对写正则至关重要。|
|**Lookaround**|Lookahead / Lookbehind|环视/断言。零宽度的匹配，只检查“周围有没有”，不消耗字符。|

### 🛠️ 5. 实操建议 (Actionable Advice)

- **练习工具**：不要直接在代码里写正则，先去 [Regex101.com](https://regex101.com/) 调试。它可以高亮显示匹配过程，并解释每一部分的含义 。
    
- **构建策略**：遇到复杂的正则（如密码验证），不要试图从左到右一次写完。采用 **Compositional approach（组合法）**：先写匹配数字的部分，再写匹配大写字母的部分，最后用逻辑操作符把它们组合起来 。
    
- **Python 技巧**：永远使用 `r"pattern"` 来定义正则表达式，否则你会被反斜杠地狱（Backslash hell）折磨 。

### 🧠 6. 复习速查卡 (Review Flashcards)

**Q1: `*` 和 `+` 的区别是什么？**

- A: `*` 匹配 **0次或多次**；`+` 匹配 **1次或多次**。如果不确定是否存在，用 `*`；如果必须至少有一个，用 `+` 。
    
    +1
    

**Q2: 如何将贪婪匹配 `.*` 变为非贪婪匹配？**

- A: 在操作符后加一个问号，变成 `.*?` 。
    

**Q3: 解释 Python 代码 `re.findall(r'\d+', "High 5 to 10")` 的输出。**

- A: `['5', '10']`。它会找到所有连续的数字序列并以列表形式返回 。
    

**Q4: 什么时候**不应该**使用正则表达式？**

- A: 当解析 HTML/XML（结构嵌套太复杂）、处理极度不规范的口语文本、或者代码需要被他人反复维护阅读时（Regex 可读性差）。
    

**Q5: `(?=pattern)` 是什么意思？**

- A: 正向先行断言 (Positive Lookahead)。意思是“确认当前位置右边有 `pattern`”，但并不将 `pattern` 计入匹配结果（不消耗字符）。
